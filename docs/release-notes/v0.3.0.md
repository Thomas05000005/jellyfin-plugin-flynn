# Flynn v0.3.0

Storage was counting the same disk several times over.

## What was wrong

A Docker media server normally bind-mounts one pool at several paths, one per library. From inside
the container each of those is a separate mount, and .NET reports each as its own drive with its
own free space. Flynn believed it.

On the server this was found on, six libraries live on one ZFS pool and two on another. Flynn saw
eight devices, and the free space of the first pool six times. Summing that overstates headroom
sixfold. The capacity forecast being built next would not have been slightly off; it would have
been confidently wrong, which is worse than absent.

## What it does now

It reads the kernel's mount table, where every mount of a filesystem carries the same device id
however many places it is bound to. Eight mounts, two filesystems, and the answer falls out.

It also names the pool the way you named it. "96% used on RAID-Z1" rather than "96% used on
/data/Films", which read as though that one folder were the problem when the whole pool is.

## Two bugs found on the way

The kernel escapes spaces in paths as ` `, so a library called *Famille priver* arrives with
the space encoded. Taking the field literally means never matching the path it belongs to.

The decoder validated those escape sequences as decimal and then converted them as octal. That
accepts ` ` by luck and silently rejects `\`, the escaped backslash, along with everything
above `` -- and a rejected sequence is copied through as-is, so the path quietly stops
matching itself.

## Requires

Jellyfin **12.0 or later**.
