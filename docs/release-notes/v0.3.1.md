# Flynn v0.3.1

Closes a hole in the fix that shipped one version ago.

## What v0.3.0 got right, and where it stopped

v0.3.0 grouped disks by the kernel's device id, which correctly folds several bind mounts of one
filesystem into a single entry. On the server this was written for, six libraries are
subdirectories of one ZFS dataset, so they share a device id and the grouping worked.

It works because of how that server happens to be laid out today, not because the rule is
complete. ZFS allocates an anonymous superblock per dataset, so two datasets of the **same pool**
carry **different** device ids while competing for exactly the same free space. Splitting a
library into its own dataset -- a normal thing to do, and something already planned there -- would
have quietly restored the double counting, with no error and no visible change.

## What it does now

Filesystems that share one budget are grouped by that budget: the pool for ZFS and Btrfs, the
device id for everything that owns its space outright. The pool is the first component of the
dataset name, which the kernel reports through the filesystem's own `show_devname` and is
therefore reliable across bind mounts, remounts and renames.

Pool names sharing a prefix stay apart: `RAID-Z1` and `RAID-Z10` are different pools, and the name
is cut at the separator rather than matched by prefix.

## Requires

Jellyfin **12.0 or later**.
