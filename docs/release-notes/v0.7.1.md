# Flynn v0.7.1

A number that described nothing.

## What the card was saying

```
11 % des titres ont une valeur de sonie
22350 titres sur 197277
```

Thomas has two music libraries. One had its loudness scan switched on and sits at **100%**. The
other never did and sits at **0%**. The card averaged them.

**No library on that server is at 11%.** The figure was arithmetically correct and completely
useless: it described neither situation, and suggested no action. He read it and said he did not
understand — which is the only review that matters for a number meant to be acted on.

## What it says now

```
Musiques2 : 0 % des titres ont une valeur de sonie
La mesure de sonie du serveur est desactivee sur cette bibliotheque, donc rien n'y a jamais ete
mesure. Elle est desactivee par defaut. Sur le reste de vos bibliotheques musicales : 100 % couverts.
```

The library that needs attention, by name, with its own coverage. Then why — because 0% reads as a
disaster when it is a setting. Then how the rest of the server looks, so a single bad library does
not read as a broken server.

## The test that was missing

Every existing test used a single library, so none of them could see the averaging. The new one
sets up exactly the two-library case and asserts the headline names the worst library rather than a
mean.

Verified by restoring the previous card and running it: `Expected: Musiques2 / Actual: 11` — the
test catches the literal number that appeared on screen.

## Wording

`music.scan-off` said the scan was off "for every music library". That was true when the card only
ever spoke about all of them at once, and became false the moment it named one. It now describes
the library it is attached to.

The other-libraries line carries no count, deliberately: any phrasing with a number needs singular
and plural agreement, and the first version got "1 autres bibliothèques" wrong.
