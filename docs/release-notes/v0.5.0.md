# Flynn v0.5.0

Adds **Resources**: what Jellyfin actually costs.

## Transcodes included, which is the whole point

`Process.GetCurrentProcess()` sees the .NET process and nothing else. On a media server most of
the CPU is spent by ffmpeg children, so a process-level reading shows a nearly idle server in the
middle of four simultaneous transcodes.

The figures come from the container's control group instead, which counts the whole tree.

## Three ways to report a confidently wrong number, avoided

**Page cache is not memory in use.** The control group is charged for cache it will hand straight
back under pressure. On the server this was built against, 2.9 GB of the 5.1 GB charged was
reclaimable -- reporting the charged figure would have overstated what Jellyfin needs by more than
double. It is the same trap as reading ZFS ARC out of `free` and calling it used.

**CPU time is charged across every core.** Dividing it by elapsed time alone gives "600%" on a six
core box. The denominator is elapsed time multiplied by the cores available, so six cores fully
busy reads as one hundred percent.

**Throttling is a share of periods, not of time.** Throttled time accumulates per CPU and cheerfully
exceeds a hundred percent on a multi-core machine. The dimensionless ratio cannot.

## What it says when it cannot measure

cgroup v2 on Linux, or nothing. Where the counters are unreadable the card says so rather than
reporting zeros, and cgroup v1 is refused outright instead of half-supported.

A rate needs two readings, so the first view after a restart says it is measuring.

## Requires

Jellyfin **12.0 or later**, and cgroup v2 for this module specifically.
