# Flynn v0.6.1

Six defects an adversarial review found in v0.6.0, published four hours earlier. One of them was
reproduced in a real browser rather than argued about.

## The escaping was safe in text and unsafe in an attribute

`esc()` set `textContent` and read `innerHTML` back. That escapes `&`, `<` and `>` — and nothing
else, because a serialiser has no reason to touch a quote inside a text node.

Which is correct, for text. It was also being used inside five attribute values. A subject
containing a double quote therefore closed the attribute early: the rest of it was parsed as
further attributes, `data-flynn-fp` silently truncated, and with the right text an event handler
appeared on the element and *actually ran*. The review demonstrated `onmouseover="alert(1)"`
compiling as a live handler.

Nothing produces such a subject today — a device id is `major:minor` or `zfs:pool`. But the
documented contract for a subject is *a device id, an album, a path*, and:

- an album called `"Heroes"` is written with the quotes,
- a macOS volume may legally be named `Films "4K"`, and `DriveProbe` uses the raw mount path as the
  device id off Linux,
- the Music module, which is next, produces album titles as subjects.

Fixed, and gated: `build/test_client_escaping.js` lifts the real `esc()` out of `admin.js` and runs
the review's own inputs through it, in CI and again at release. Removing the fix turns it red.

## An expired snooze was in two places at once

The list promoted a snooze whose date had passed back to open. The tally counted the stored value.
So the same issue sat in the inbox *and* in the "hidden" count printed underneath it.

## Dismissing something that had already closed itself

`SetStateAsync` had no predicate on the current state, so dismissing a resolved issue answered 204
and added it to the dismissed count — inventing a decision nobody made, in the very tally that
exists to record decisions. It now answers 404.

## The actions did not check the database was up

`GET /Flynn/issues` answered a clean 503 with the reason. The three actions beside it went straight
at a database that was not there. They now share one guard.

## A snooze now says until when

`IssueDto` reported `State` but not `SnoozedUntil`, so the page could say *hidden* and not *hidden
until Tuesday*. The server held the date and dropped it on the way out.

---

252 tests. The two registry fixes were verified by restoring the old file and watching the new
tests fail; the escaping gate by removing the fix and watching it refuse.

**Also in this release**: `AssetsController` and `ResourcesModule` had no tests at all and now do —
including one that asserts every embedded asset is really in the assembly, since a lost
`EmbeddedResource` entry produces a plugin that loads, reports healthy and quietly does nothing.
`CgroupReader.IsAvailable` no longer asks whether the OS is Linux; the file either exists or it
does not, and the extra check made the module untestable anywhere but the build machine.
