# Flynn v0.6.0

The inbox becomes something you can act on, and a defect that had been hiding behind another one
gets fixed.

## Dismiss, snooze, bring back

The three endpoints already existed, were exposed, and were tested at the registry level. They
could not work.

An issue is identified by a fingerprint built as `module/kind/subject`, and the subject is whatever
the module names — on this server's pooled storage that is `zfs:RAID-Z1`, so a real fingerprint
reads `capacity/capacity/zfs:RAID-Z1`. They were declared as `issues/{fingerprint}/dismiss`, and a
route segment cannot match a value containing slashes. Percent-encoding does not rescue it either:
the path is decoded before routing sees it, and the slashes come back as separators.

Nobody noticed because the admin page never called them. Two defects hiding each other, neither
visible from the layer the other was tested at. The fingerprint now travels in the query string,
and a test reads the route attributes directly — the behaviour tests call the methods, which proves
nothing about routing.

## What is hidden is now visible

Dismissal is permanent by design. That is only acceptable if there is a way back, and a count on
its own is not one: knowing three issues are hidden without being able to see which three is a
slightly better blind spot. The withheld line now opens onto the list, each row with a button.

Resolved issues are not in it. Nobody hid those — they closed themselves, and listing them would
bury the ones that were actually a decision.

## Eleven French strings that shipped without their accents

`coute`, `utilises`, `coeurs`, `recuperable`, `releves`, `Capacite`. The ASCII rule exists because
some Jellyfin client paths decode the *injected scripts* as latin1; it has never applied to the
UTF-8 string catalogues, which the server reads directly. Applying it there was a mistake, and this
is the second time it has been made.

## The CPU percentage now says what it is a share of

"23% CPU of 6 cores" rather than "23% CPU". Eighty percent of an imposed quota means throttling is
about to start; eighty percent of a whole machine means busy. The distinction was computed in
v0.5.0 and then not displayed.

## Housekeeping

- Resolved issues age out after 90 days, applied mutation records after a year. **Storage readings
  are kept forever** — a hundred kilobytes a year, and the forecast caps its horizon at twice the
  history it can see, so pruning them would shorten how far ahead Flynn is willing to predict.
  Dismissed issues are kept forever too.
- `ForecastModule` was registered twice, which built two instances: the dashboard rendered one and
  the nightly task drove the other. Harmless only while the module stays stateless.
- Refusing a configuration write now answers 400 with the reason instead of 500.
- The client runtime reads its version from its own script tag instead of a constant, which had
  been claiming 0.1.0 for five releases.

228 tests. The retention guards and the route guard were each verified by reintroducing the defect
and watching them fail.
